第 3 课：SQLite 数据库操作

从 SQL 到 better-sqlite3 — 用 Open Design 的真实代码学数据库 · 预计 25 分钟

better-sqlite3 是什么？

Open Design 用 better-sqlite3 操作 SQLite。它是一个同步的 Node.js SQLite 驱动——所有操作都在当前线程完成，不需要 async/await。

大多数数据库驱动（异步）
const user = await db.query(
  'SELECT * FROM users WHERE id = ?', [id]
);
better-sqlite3（同步）
const user = db.prepare(
  'SELECT * FROM users WHERE id = ?'
).get(id);
💡 为什么是同步的？SQLite 是文件数据库，所有操作都在本机磁盘上完成，没有网络 IO。同步操作足够快（微秒级），不会阻塞 Node.js 事件循环。

核心 API：三步走

第 1 步：打开数据库

import Database from 'better-sqlite3';

const db = new Database('app.sqlite');
db.pragma('journal_mode = WAL');  // 启用 WAL 模式（性能优化）

第 2 步：准备 SQL 语句

// prepare() 创建一个可复用的语句对象
const insertProject = db.prepare(`
  INSERT INTO projects (id, name, skill_id, created_at, updated_at)
  VALUES (?, ?, ?, ?, ?)
`);

第 3 步：执行语句

// .run() — 执行写操作（INSERT/UPDATE/DELETE），返回变更信息
insertProject.run('p1', '我的项目', 'deck-creator', Date.now(), Date.now());

// .get() — 查询一行，返回对象或 undefined
const project = db.prepare('SELECT * FROM projects WHERE id = ?').get('p1');

// .all() — 查询多行，返回数组
const projects = db.prepare('SELECT * FROM projects').all();

Open Design 中的真实代码

打开 apps/daemon/src/db.ts，你会看到这样的代码：

建表（migrate 函数）

function migrate(db: SqliteDb): void {
  db.exec(`
    CREATE TABLE IF NOT EXISTS projects (
      id TEXT PRIMARY KEY,
      name TEXT NOT NULL,
      skill_id TEXT,
      design_system_id TEXT,
      pending_prompt TEXT,
      metadata_json TEXT,
      created_at INTEGER NOT NULL,
      updated_at INTEGER NOT NULL
    );
  `);
}

要点：

  • IF NOT EXISTS — 已存在就不重建，安全的幂等操作
  • TEXT PRIMARY KEY — 用 UUID 字符串做主键，不是自增整数
  • INTEGER NOT NULL — 时间戳用整数存储（Unix 毫秒）
  • JSON TEXT — SQLite 没有 JSON 类型，用 TEXT 存 JSON 字符串

查询（典型的 CRUD 操作）

// 创建项目
db.prepare(`
  INSERT INTO projects (id, name, skill_id, created_at, updated_at)
  VALUES (?, ?, ?, ?, ?)
`).run(id, name, skillId, now, now);

// 查询单个项目
const project = db.prepare('SELECT * FROM projects WHERE id = ?').get(id);

// 查询项目列表
const projects = db.prepare('SELECT * FROM projects ORDER BY updated_at DESC').all();

// 更新项目
db.prepare('UPDATE projects SET name = ?, updated_at = ? WHERE id = ?')
  .run(newName, now, id);

// 删除项目（级联删除关联的 conversations、messages 等）
db.prepare('DELETE FROM projects WHERE id = ?').run(id);

参数占位符

// ? — 位置参数（按顺序填入）
db.prepare('SELECT * FROM projects WHERE id = ?').get(id);

// ?1, ?2 — 命名位置参数（可重复使用）
db.prepare('SELECT * FROM messages WHERE conversation_id = ?1 AND role = ?2')
  .all(convId, 'assistant');

// :name, @name, $name — 命名参数（传对象）
db.prepare('INSERT INTO projects (id, name) VALUES (:id, :name)')
  .run({ id: 'p1', name: '我的项目' });

事务（Transaction）

当需要批量执行多条 SQL时，用事务保证原子性——要么全部成功，要么全部失败。

// 不用事务：每条 SQL 单独执行，中途失败会留下半成品
db.prepare('INSERT INTO projects ...').run(id, ...);
db.prepare('INSERT INTO conversations ...').run(convId, ...);  // ← 这里失败了
db.prepare('INSERT INTO messages ...').run(msgId, ...);         // ← 不会执行

// 用事务：要么全部成功，要么全部回滚
const createProjectWithConversation = db.transaction((project, conversation) => {
  db.prepare('INSERT INTO projects ...').run(project.id, ...);
  db.prepare('INSERT INTO conversations ...').run(conversation.id, ...);
  db.prepare('INSERT INTO messages ...').run(msgId, ...);
});

createProjectWithConversation(project, conversation);  // 原子操作
💡 better-sqlite3 的事务性能：100 条 INSERT 不用事务需要 ~100ms，用事务只需要 ~1ms。因为每次写操作都要刷磁盘，事务把多次刷盘合并为一次。

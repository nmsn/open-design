第 6 课：SSE 流式通信

Server-Sent Events — AI 实时回复的传输机制 · 预计 25 分钟

什么是 SSE？

SSE（Server-Sent Events）是 HTML5 标准，允许服务端单向推送数据到浏览器。它基于普通 HTTP 长连接，比 WebSocket 简单。

为什么 AI 应用几乎都用 SSE？

  • ✅ AI 回复是单向流（服务端 → 客户端），不需要客户端反向发消息
  • ✅ 基于 HTTP，无需额外协议升级
  • ✅ 浏览器原生支持 EventSource API
  • ✅ 自动重连

SSE vs WebSocket vs 长轮询

特性SSEWebSocket长轮询
方向单向（服务器→浏览器）双向单向
协议HTTP独立协议HTTP

SSE 协议格式

SSE 是一种非常简单的文本协议，每个事件用 `\n\n` 分隔：

event: start
data: {"model": "claude-sonnet-4"}

event: delta
data: {"delta": "你好"}

event: delta
data: {"delta": "，我是"}

event: delta
data: {"delta": " Claude"}

event: end
data: {}

每个字段说明：

  • event: <name> — 事件类型（如 start、delta、end）
  • data: <json> — 事件数据（一行 JSON）
  • id: <num> — 事件 ID（用于断线重连，浏览器自动发 Last-Event-ID）
  • : comment — 注释行（浏览器忽略，常用于心跳保活）

服务端实现（Node.js）

最简实现

app.get('/api/stream', (req, res) => {
  // 1. 设置 SSE 响应头
  res.setHeader('Content-Type', 'text/event-stream');
  res.setHeader('Cache-Control', 'no-cache');
  res.setHeader('Connection', 'keep-alive');
  res.flushHeaders();  // 立即发送头部

  // 2. 发送事件
  res.write('event: message\ndata: {"text": "hello"}\n\n');
  res.write('event: message\ndata: {"text": "world"}\n\n');
  res.write('event: end\ndata: {}\n\n');

  // 3. 关闭连接
  res.end();
});

心跳保活

const heartbeat = setInterval(() => {
  res.write(': keepalive\n\n');  // 注释行，浏览器忽略但保持连接
}, 15000);

// 用户断开时清理
req.on('close', () => clearInterval(heartbeat));
💡 为什么需要心跳？中间代理（nginx、CDN）经常会在 30-60 秒没有数据时断开连接。心跳保持连接活跃。

Open Design 中的实现

Open Design 在 apps/daemon/src/server.ts 的 createSseResponse() 中封装了完整的 SSE 工具：

createSseResponse()

export function createSseResponse(res) {
  res.setHeader('Content-Type', 'text/event-stream');
  res.setHeader('Cache-Control', 'no-cache, no-transform');
  res.setHeader('Connection', 'keep-alive');
  res.setHeader('X-Accel-Buffering', 'no');  // 关掉 nginx 缓冲
  res.flushHeaders();

  let heartbeat = setInterval(() => {
    res.write(': keepalive\n\n');
  }, 15000);

  return {
    send(event, data) {
      // 注意：单个 write 调用，把 event/data 写在一个 TCP 包里
      res.write(`event: ${event}\ndata: ${JSON.stringify(data)}\n\n`);
    },
    end() {
      clearInterval(heartbeat);
      res.end();
    }
  };
}

为什么单个 write 很重要？

// ❌ 三次 write — 可能在不同 TCP 包到达
res.write(`event: ${event}\n`);
res.write(`data: ${JSON.stringify(data)}\n`);
res.write('\n');

// ✅ 一次 write — 一定在同一个 TCP 包
res.write(`event: ${event}\ndata: ${JSON.stringify(data)}\n\n`);
💡 关键细节：如果分多次写，前端可能先收到 event: start 但 data 还在路上，导致解析器看到一个不完整的事件。Open Design 的代码注释专门强调了这一点。

客户端实现（浏览器）

原生 EventSource

const es = new EventSource('/api/stream');

es.addEventListener('start', (e) => {
  console.log('开始:', JSON.parse(e.data));
});

es.addEventListener('delta', (e) => {
  const data = JSON.parse(e.data);
  appendText(data.delta);  // 增量渲染
});

es.addEventListener('end', (e) => {
  console.log('结束');
  es.close();
});

es.onerror = (e) => {
  console.error('连接出错，自动重连中...');
};

Open Design 用的是 fetch + ReadableStream

Open Design 的 web 前端不用 EventSource，而是用 fetch + ReadableStream，因为 EventSource 不支持自定义请求头（如 Authorization）。

// 前端代码（伪代码）
const response = await fetch('/api/chat', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'Authorization': '...' },
  body: JSON.stringify({ prompt: '你好' }),
});

const reader = response.body.getReader();
const decoder = new TextDecoder();
let buffer = '';

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });

  // 按 \n\n 分帧解析
  const frames = buffer.split('\n\n');
  buffer = frames.pop() ?? '';

  for (const frame of frames) {
    const event = parseFrame(frame);
    if (event.name === 'delta') appendText(event.data.delta);
    if (event.name === 'end') break;
  }
}

AI 流式回复的完整链路

用户输入提示词 │ ▼ Web: POST /api/chat │ ▼ Daemon: createSseResponse(res) │ ▼ Daemon: fetch(AI API, { stream: true }) │ ▼ AI API 流式输出 JSONL │ data: {"choices":[{"delta":{"content":"你"}}]} │ data: {"choices":[{"delta":{"content":"好"}}]} │ data: [DONE] ▼ Daemon: streamUpstreamSse() 逐帧解析 │ ├── 文本 → sse.send('delta', { delta: '你' }) ├── 文本 → sse.send('delta', { delta: '好' }) │ ▼ Web: fetch().body.getReader() 流式读取 │ ├── 收到 delta '你' → 渲染 ├── 收到 delta '好' → 渲染 │ ▼ 用户看到 "你好" 一个字一个字出现

第 7 课：Agent 适配器模式

检测、注册、启动、流解析 — 理解 Open Design 如何支持 22+ 代理 · 预计 30 分钟

问题：22+ 代理如何统一管理？

Open Design 支持 Claude Code、Codex、Cursor、Gemini CLI、Qwen、Hermes 等 22+ 编码代理 CLI。每个代理的：

  • 📦 安装路径不同（npm/pip/cargo/curl）
  • 🚀 启动参数不同（不同 CLI flags）
  • 📡 输出格式不同（JSONL / NDJSON / 自定义）
  • 🔌 通信协议不同（spawn 直连 / ACP）

如果不抽象，每个新代理都要改 N 处代码。Open Design 用适配器模式**解决了这个问题。

适配器模式

┌──────────────────────────────┐ │ Daemon (统一的代理接口) │ └──────────────┬───────────────┘ │ ┌──────────────┴───────────────┐ │ RuntimeAgentDef (接口) │ └──────────────┬───────────────┘ │ ┌──────────┬────────────┼────────────┬──────────┐ ▼ ▼ ▼ ▼ ▼ Claude Codex Hermes Aider Gemini 适配器 适配器 适配器 适配器 适配器

每个代理实现同一套接口，Daemon 只跟接口交互。

RuntimeAgentDef 接口

打开 apps/daemon/src/runtimes/types.ts，看接口定义：

interface RuntimeAgentDef {
  id: string;                              // 'claude', 'codex', 'hermes'
  label: string;                           // 'Claude Code', 'OpenAI Codex'
  family: 'claude' | 'openai' | 'gemini' | 'custom';
  bin: string;                             // 默认二进制名 'claude'
  versionProbe: VersionProbe;              // 如何检测版本
  spawn: SpawnConfig;                      // 启动参数
  streamFormat: 'jsonl' | 'ndjson' | 'acp'; // 输出格式
  capabilities: AgentCapabilities;         // 功能矩阵
  // ...
}

四步代理生命周期

1. 检测 (detection.ts) └─ 用户机器上有 claude 吗？→ /usr/local/bin/claude 2. 注册 (registry.ts) └─ 把代理定义加载到内存中的注册表 3. 启动 (launch.ts + acp.ts / codex-cli.ts) └─ spawn 子进程，传入参数 4. 流解析 (claude-stream.ts / json-event-stream.ts / acp.ts) └─ 解析 stdout JSONL，归一化为统一事件

第 1 步：检测

apps/daemon/src/runtimes/detection.ts

// 检测系统里有哪些代理 CLI
async function detectAgents(): Promise {
  const detected = [];
  for (const def of ALL_AGENT_DEFS) {
    const path = await findExecutable(def.bin);
    if (path) {
      detected.push({ ...def, resolvedPath: path });
    }
  }
  return detected;
}

// 在 PATH 和用户工具链目录中找
async function findExecutable(bin: string) {
  const dirs = [
    ...process.env.PATH.split(':'),
    ...wellKnownUserToolchainBins(),  // ~/.npm, ~/.cargo/bin 等
  ];
  for (const dir of dirs) {
    const candidate = path.join(dir, bin);
    if (await exists(candidate)) return candidate;
  }
  return null;
}
💡 为什么要扫描用户工具链目录？nvm、fnm、mise、asdf 等工具会把 CLI 装在用户目录（如 ~/.nvm/versions/node/v20/bin），不在系统 PATH 中。需要单独扫描这些位置。

第 2 步：注册

apps/daemon/src/runtimes/registry.ts

// 维护一个全局注册表
const AGENT_REGISTRY = new Map();

export function registerAgent(def: RuntimeAgentDef) {
  AGENT_REGISTRY.set(def.id, def);
}

export function getAgent(id: string): RuntimeAgentDef {
  return AGENT_REGISTRY.get(id);
}

export function listAgents(): RuntimeAgentDef[] {
  return Array.from(AGENT_REGISTRY.values());
}

所有代理定义在 runtimes/defs/*.ts 中，启动时一次性注册。

第 3 步：启动

spawn 直连模式（Claude Code / Codex / Aider 等 12 个）

// apps/daemon/src/runtimes/launch.ts — 只解析路径
const resolution = resolveAgentLaunch(def);
const binPath = resolution.launchPath;  // '/usr/local/bin/claude'

// 各代理自己的启动逻辑（codex-cli.ts / acp.ts / ...）
import { spawn } from 'node:child_process';
const child = spawn(binPath, def.spawn.args, {
  env: buildAgentEnv(def),
  cwd: projectDir,
  stdio: ['pipe', 'pipe', 'pipe'],
});

ACP 协议模式（Hermes / Kilo / Kiro 等 13 个）

// apps/daemon/src/acp.ts — 统一 ACP 客户端
import { spawn } from 'node:child_process';
import { createAcpClient } from './acp.js';

const client = createAcpClient({
  bin: 'hermes',
  args: ['--acp'],
});

await client.connect();
await client.sessionNew({ model: 'gpt-4' });
await client.prompt({ sessionId, content: prompt });

// 监听流式事件
client.on('text_chunk', (delta) => {
  sse.send('delta', { delta });
});
## 第 4 步：流解析 每个代理的 stdout 格式都不同，需要不同的解析器归一化为统一事件：
代理原始格式解析器
Claude CodeAnthropic SSEclaude-stream.ts
CodexJSONL (OpenAI 格式)codex-stream.ts
通用 JSONLNDJSONjson-event-stream.ts
ACP 代理JSON-RPC 2.0acp.ts
### 归一化为统一事件 所有解析器最终都把数据转成同样的内部事件： ```ts type AgentEvent = | { type: 'start', model: string } | { type: 'text_delta', text: string } | { type: 'tool_use', id: string, name: string, input: any } | { type: 'tool_result', id: string, content: any } | { type: 'finish', reason: string } | { type: 'error', message: string }; ``` Daemon 上层只处理这个统一类型，**不再关心底层代理是谁**。 ## 能力矩阵（Capabilities） 不同代理支持不同功能，比如： ```ts interface AgentCapabilities { supportsResume: boolean; // 是否支持恢复会话 supportsMcp: boolean; // 是否支持 MCP supportsImageGeneration: boolean; supportsVideoGeneration: boolean; maxContextTokens: number; } ``` 调用前先检查： ```ts if (agent.capabilities.supportsImageGeneration) { // 注入图片生成工具 } else { // 不显示给用户 } ``` ## 新增一个代理的步骤 如果要支持一个新代理（如 "MyAgent"）： ```ts // 1. 创建 apps/daemon/src/runtimes/defs/myagent.ts export const myAgentDef: RuntimeAgentDef = { id: 'myagent', label: 'My Agent', family: 'custom', bin: 'myagent', versionProbe: { args: ['--version'], parse: parseSemver }, spawn: { args: ['--acp'], // 或自定义 JSONL 格式 env: { ... }, }, streamFormat: 'acp', // 或 'jsonl' capabilities: { ... }, }; // 2. 在 registry.ts 中注册 import { myAgentDef } from './defs/myagent.js'; registerAgent(myAgentDef); ``` **只需要 2 个文件**，无需改 daemon 核心代码。这就是适配器模式的力量。 ## 检查理解

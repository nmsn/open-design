第 1 课：项目全景与全栈心智模型

从你熟悉的前端出发，建立对 Open Design 全栈架构的完整心智模型 · 预计 20 分钟

你已经知道的

作为前端开发者，你熟悉这个流程：

用户 → 浏览器 → React 组件 → fetch() → 某个 API → 返回 JSON → 渲染 UI

在 Open Design 中，apps/web 就是你熟悉的这一层。但"某个 API"背后，是一个完整的 Node.js 后端——这就是你要学习的部分。

Open Design 的三层架构

┌─────────────────────────────────────────────────────┐ │ 浏览器 (你已经懂) │ │ apps/web — Next.js 16 + React 18 │ └──────────────────────┬──────────────────────────────┘ │ HTTP / SSE ▼ ┌─────────────────────────────────────────────────────┐ │ 守护进程 (你要学的) │ │ apps/daemon — Express 5.2 + SQLite │ │ ├── /api/* 路由 ← HTTP 接口 │ │ ├── db.ts ← 数据库 │ │ ├── runtimes/ ← 代理编排 │ │ └── routes/ ← 业务逻辑 │ └──────────────────────┬──────────────────────────────┘ │ 子进程 stdin/stdout ▼ ┌─────────────────────────────────────────────────────┐ │ 代理 CLI (外部工具) │ │ Claude Code, Codex, Cursor, Gemini CLI ... │ └─────────────────────────────────────────────────────┘

一个请求的完整旅程

当你在 Open Design 的聊天界面输入提示词并发送：

  1. 前端：React 组件调用 POST /api/chat
  2. 路由：Express 匹配到 routes/chat.ts
  3. 数据库：在 SQLite 中创建会话和消息记录
  4. 代理编排：runtimes/launch.ts 生成一个子进程运行 Claude Code
  5. 流式传输：代理的 stdout 输出被解析为事件，通过 SSE 推送给前端
  6. 渲染：前端在沙箱 iframe 中渲染生成的 HTML 制品
💡 关键洞察：整个后端的核心工作就是"编排"——接收前端请求，调度外部代理，把结果流式传回。它本身不做 AI 推理，而是连接用户和 AI 代理的桥梁。

动手探索

现在你对架构有了整体认识，试试以下操作：

  1. 打开 apps/daemon/src/server.ts，搜索 app.get 和 app.post，看看有哪些路由
  2. 打开 apps/daemon/src/db.ts，找到 CREATE TABLE 语句，看看数据库有哪些表
  3. 打开 apps/daemon/src/routes/chat.ts，找到 SSE 推送的代码（搜索 res.write）

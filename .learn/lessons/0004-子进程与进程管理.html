第 4 课：子进程与进程管理

child_process、spawn、stdin/stdout — 理解 Open Design 如何调度 AI 代理 · 预计 25 分钟

为什么需要子进程？

Open Design 本身不运行 AI 模型，而是通过启动外部代理 CLI（如 Claude Code）来完成工作。这意味着：

Daemon (Node.js) │ ├── spawn → Claude Code 子进程 (独立进程) │ │ │ ├── stdin: 接收提示词 │ ├── stdout: 流式输出 AI 回复 │ └── stderr: 错误日志 │ ├── spawn → Codex 子进程 │ └── spawn → Gemini CLI 子进程

每个代理都是一个独立进程，运行在自己的 Python/Rust/Node 环境中。Daemon 通过进程间通信（IPC）协调它们。

Node.js 的 child_process 模块

方法特点用途
spawn流式，不缓冲长期运行的进程、流式输出
exec缓冲完整输出短命令、捕获完整输出
execFile类似 exec 但更安全执行指定文件
fork创建 Node.js 子进程Node-to-Node 通信
💡 Open Design 几乎只用 spawn，因为代理 CLI 的输出是流式的（一个字符一个字符地输出），不能缓冲。

spawn 基础

import { spawn } from 'node:child_process';

// 最简单的 spawn
const child = spawn('ls', ['-la', '/tmp']);

// 监听输出
child.stdout.on('data', (chunk) => {
  console.log('stdout:', chunk.toString());
});

child.stderr.on('data', (chunk) => {
  console.error('stderr:', chunk.toString());
});

// 等待子进程结束
child.on('close', (code) => {
  console.log(`进程退出，码 ${code}`);
});

打开 apps/daemon/src/runtimes/launch.ts，你会看到类似的代码：

启动 Claude Code 子进程

const child = spawn('claude', [
  '--print',                       // 打印输出模式
  '--output-format', 'stream-json',// 流式 JSON 输出
  '--session-id', sessionId,       // 会话 ID
], {
  env: { ...process.env, ...customEnv },  // 继承环境变量
  cwd: projectDir,                          // 工作目录
  stdio: ['pipe', 'pipe', 'pipe'],         // 三个流都可读可写
});

// 监听代理输出
child.stdout.on('data', (chunk: Buffer) => {
  parseAgentOutput(chunk, (event) => {
    sse.send('delta', { delta: event.text });
  });
});

// 监听代理错误
child.stderr.on('data', (chunk: Buffer) => {
  console.error('[agent stderr]', chunk.toString());
});

// 进程退出
child.on('exit', (code) => {
  sse.send('end', { exitCode: code });
});

stdin/stdout 双向通信

spawn 默认三个流都是 pipe（管道），可以双向通信：

Daemon Agent CLI │ │ ├── stdin.write(prompt) ───────→ │ 接收提示词 │ │ │ ←────── stdout.on('data') ────┤ 流式输出回复 │ │ │ ←────── stderr.on('data') ────┤ 错误日志 │ │ ├── child.kill('SIGTERM') ─────→ │ 优雅退出 │ │

写入子进程 stdin

// 给子进程发送多轮对话
child.stdin.write('第一轮问题\n');
// ... 等一会儿
child.stdin.write('第二轮问题\n');
child.stdin.end();  // 关闭输入，子进程会处理完已收到的内容后退出

超时与杀进程

// 设置超时（30 秒没响应就杀进程）
const timeout = setTimeout(() => {
  console.warn('代理超时，强制结束');
  child.kill('SIGTERM');   // 优雅退出（允许子进程清理）
  setTimeout(() => child.kill('SIGKILL'), 5000); // 5 秒后强杀
}, 30000);

child.on('exit', () => clearTimeout(timeout));

进程管理

获取 PID 和检测进程存活

// 获取子进程 PID
const pid = child.pid;

// 检测进程是否还活着
try {
  process.kill(pid, 0);  // signal 0 = 不杀，只检测
  console.log('进程存活');
} catch (e) {
  console.log('进程已死');
}

进程组（Process Group）

默认情况下，spawn 不会创建新的进程组——子进程的子进程和 Daemon 在同一个组里。杀子进程不会杀孙进程。

// detached: true 创建独立的进程组
const child = spawn('claude', args, {
  detached: true,   // 创建新进程组
  stdio: 'ignore',
});

// 可以通过进程组 ID 杀整个组
process.kill(-child.pid, 'SIGTERM');  // 负号 = 进程组

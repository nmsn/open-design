第 9 课：MCP 协议入门

Model Context Protocol — AI 工具调用的标准化协议 · 预计 25 分钟

什么是 MCP？

MCP (Model Context Protocol) 是 Anthropic 推出的开放协议，标准化了 AI 模型如何调用外部工具和数据源。

💡 一句话：MCP = AI 的 USB 协议。让任何 AI 客户端都能调用任何 MCP 服务器提供的工具，就像 USB 设备插到电脑上就能用。

没有 MCP 之前

每个 AI 客户端要单独适配每个数据源：

Claude ←→ Google Drive 适配器 ←→ GitHub 适配器 ←→ Slack 适配器 ←→ Postgres 适配器 ←→ ... Cursor ←→ Google Drive 适配器 (重复) ←→ GitHub 适配器 (重复) ←→ ... (每个客户端都要为每个工具写适配器 — N × M 复杂度)

有了 MCP 之后

Claude ↘ Cursor →→ MCP 协议 →→ Google Drive MCP Server VSCode ↗ → GitHub MCP Server → Postgres MCP Server → Open Design MCP Server (每个工具写一次 MCP 服务器，所有客户端都能用 — N + M 复杂度)

MCP 的核心概念

三个角色

角色作用Open Design 中的对应
HostAI 客户端（Claude Desktop、Cursor）外部代理（Claude Code、Codex）
ClientHost 内部的 MCP 适配器代理里的 MCP client
Server提供工具/数据/提示词的服务apps/daemon（暴露工具给 AI）

三种能力（Primitive）

能力作用例子
ToolsAI 可以调用的函数读取文件、生成图片、搜索
ResourcesAI 可以读取的数据项目文件列表、设计系统文档
Prompts预定义的提示词模板"生成 PPT 大纲"、"代码审查"

MCP 通信：基于 stdio 的 JSON-RPC

MCP 服务器是一个标准进程，通过 stdin/stdout 通信：

Host (AI 客户端) │ ├── spawn MCP 服务器子进程 │ (stdio: ['pipe', 'pipe', 'pipe']) │ ├── stdin: 发送 JSON-RPC 请求 │ ←─── stdout: 接收 JSON-RPC 响应 │ ←─── stdout: 接收通知（事件） │ └── 进程退出 → 关闭连接

JSON-RPC 2.0 基础

请求（Request）

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/list",
  "params": {}
}

响应（Response）

{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "tools": [
      {
        "name": "generate_image",
        "description": "Generate an image from a text prompt",
        "inputSchema": {
          "type": "object",
          "properties": {
            "prompt": { "type": "string" },
            "size": { "type": "string", "enum": ["1024x1024", "1024x1792"] }
          },
          "required": ["prompt"]
        }
      }
    ]
  }
}

通知（Notification — 无需响应）

{
  "jsonrpc": "2.0",
  "method": "notifications/tools/updated",
  "params": { "toolName": "generate_image" }
}

调用工具（Tool Call）

// 客户端 → 服务器
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "generate_image",
    "arguments": { "prompt": "a cat in space", "size": "1024x1024" }
  }
}

// 服务器 → 客户端（响应）
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "content": [
      {
        "type": "image",
        "data": "https://...",   // 图片 URL
        "mimeType": "image/png"
      }
    ]
  }
}

MCP 服务器的实现骨架

// apps/daemon/src/runtimes/mcp.ts
import { spawn } from 'node:child_process';
import { randomUUID } from 'node:crypto';

class McpServer {
  private child: ChildProcess;
  private pendingRequests = new Map();

  async start() {
    this.child = spawn('node', ['mcp-server.js'], {
      stdio: ['pipe', 'pipe', 'pipe'],
    });

    this.child.stdout.on('data', (chunk) => {
      const lines = chunk.toString().split('\n').filter(Boolean);
      for (const line of lines) {
        const msg = JSON.parse(line);
        this.handleMessage(msg);
      }
    });

    // 发送 initialize 请求
    await this.request('initialize', {
      protocolVersion: '2025-01',
      clientInfo: { name: 'open-design', version: '0.11.1' },
    });
  }

  async callTool(name: string, args: any) {
    return await this.request('tools/call', { name, arguments: args });
  }

  private async request(method: string, params: any): Promise {
    const id = randomUUID();
    return new Promise((resolve, reject) => {
      this.pendingRequests.set(id, { resolve, reject });
      this.child.stdin.write(JSON.stringify({
        jsonrpc: '2.0', id, method, params,
      }) + '\n');
    });
  }

  private handleMessage(msg: any) {
    if (msg.id && this.pendingRequests.has(msg.id)) {
      const { resolve, reject } = this.pendingRequests.get(msg.id);
      this.pendingRequests.delete(msg.id);
      msg.error ? reject(new Error(msg.error.message)) : resolve(msg.result);
    }
  }
}

MCP 的传输方式

MCP 支持多种传输方式：

传输方式使用场景优点
stdio本地进程间通信简单、零配置
SSE远程服务器支持跨网络
HTTP未来计划最通用

Open Design 主要用 stdio 方式（同一台机器上）。

第 5 课：环境搭建与本地运行

tools-dev、端口、命名空间 — 启动 Open Design 本地开发环境 · 预计 20 分钟

为什么需要 tools-dev？

Open Design 是一个多进程应用（daemon + web + desktop），不能用 npm run dev 简单启动。tools-dev 是统一的本地生命周期控制平面。

tools-dev │ ├── start 启动所有进程 ├── stop 停止所有进程 ├── run web 启动 daemon + web（开发模式） ├── status 查看进程状态 ├── logs 查看日志 ├── inspect 桌面端调试（截图、eval、控制台） └── check 检查环境
💡 为什么不让每个 app 自己 dev？daemon 和 web 需要协调端口、命名空间、日志路径。tools-dev 统一管理这些，避免冲突。

第一次启动

安装依赖

pnpm install

启动开发环境

pnpm tools-dev run web

这会启动：

  • Daemon — Express 服务，监听 localhost:7456
  • Web — Next.js 开发服务器，监听 localhost:3000

等待几秒，看到 "ready" 提示后，浏览器打开 http://localhost:3000。

关键概念：端口与命名空间

端口（Port）

端口服务环境变量
7456Daemon HTTP APIOD_PORT
3000Next.js WebOD_WEB_PORT

自定义端口：

pnpm tools-dev run web --daemon-port 17456 --web-port 17573

命名空间（Namespace）

命名空间用于隔离不同的开发实例。多个 dev 实例可以同时运行而不冲突。

pnpm tools-dev run web --namespace my-feature

不同 namespace 的差异：

  • 数据目录：.tmp/tools-dev/my-feature/
  • IPC 路径：/tmp/open-design/ipc/my-feature/daemon.sock
  • 日志路径：.tmp/tools-dev/my-feature/daemon.log

为什么要命名空间？

想象你同时开发两个 feature，每个都需要独立的 daemon + 数据库 + 日志。命名空间让它们互不干扰——feature A 的聊天记录不会出现在 feature B 的会话里。

常用命令

查看状态

pnpm tools-dev status

查看日志

pnpm tools-dev logs --namespace main

停止

pnpm tools-dev stop

环境检查

pnpm tools-dev check

桌面端调试

pnpm tools-dev inspect desktop status
pnpm tools-dev inspect desktop screenshot --path /tmp/od.png

目录结构

运行时数据都在 .tmp/ 目录下（被 gitignore）：

.tmp/tools-dev/main/
├── daemon.log           # daemon 日志
├── web.log              # web 日志
├── status.json          # 运行时状态（PID、端口）
├── od/                  # daemon 数据
│   └── app.sqlite       # SQLite 数据库
└── ipc/                 # IPC socket
    └── main/
        ├── daemon.sock
        └── web.sock

常见问题

端口被占用

EADDRINUSE: address already in use 0.0.0.0:7456

解决方案：换端口或杀掉占用进程

lsof -ti:7456 | xargs kill -9

数据库锁定

SQLITE_BUSY: database is locked

解决方案：删除锁文件或重启 daemon

rm .tmp/tools-dev/main/od/*.db-*

动手探索

  1. 运行 pnpm install 安装依赖（首次需要几分钟）
  2. 运行 pnpm tools-dev run web 启动开发环境
  3. 浏览器打开 http://localhost:3000，确认 UI 加载
  4. 另一个终端运行 pnpm tools-dev status 查看进程状态
  5. 尝试 pnpm tools-dev run web --namespace test1 启动一个隔离实例

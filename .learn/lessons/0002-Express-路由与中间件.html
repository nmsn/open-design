React Router vs Express Router

作为前端开发者，你已经用过路由了：

概念前端 (React Router)后端 (Express)
定义路由<Route path="/users" />app.get('/users', handler)
嵌套路由<Route><Route /></Route>router.use('/users', userRouter)
路由参数useParams()req.params.id
中间件高阶组件 / Layoutapp.use(middleware)
404 页面<Route path="*" />app.use((req, res) => res.status(404))

Express 路由基础

一个路由 = 方法 + 路径 + 处理函数

// 前端写法（React）
<Route path="/api/health" element={<HealthPage />} />

// 后端写法（Express）
app.get('/api/health', async (req, res) => {
  res.json({ status: 'ok' });
});

Express 的路由方法对应 HTTP 方法：

app.get('/api/projects', handler)     // 读取
app.post('/api/projects', handler)    // 创建
app.put('/api/projects/:id', handler) // 更新
app.delete('/api/projects/:id', handler) // 删除

路由参数

// 前端：/projects/:id
const { id } = useParams();

// 后端：/api/projects/:id
const id = req.params.id;

请求体

// 前端
fetch('/api/projects', {
  method: 'POST',
  body: JSON.stringify({ name: '新项目' })
});

// 后端
const { name } = req.body;  // 自动解析 JSON

模块化路由（Router）

Open Design 把路由拆分到独立文件，用 express.Router() 组织：

// routes/project.ts — 项目相关路由
import { Router } from 'express';
const router = Router();

router.get('/', listProjects);       // GET  /api/projects
router.post('/', createProject);     // POST /api/projects
router.get('/:id/files', getFiles);  // GET  /api/projects/:id/files

export default router;
// server.ts — 注册路由模块
import projectRoutes from './routes/project/index.js';

// 所有 /api/projects/* 请求交给 projectRoutes 处理
app.use('/api/projects', projectRoutes);
请求: GET /api/projects/p123/files │ ▼ server.ts │ app.use('/api/projects', projectRoutes) ▼ routes/project/index.ts │ router.get('/:id/files', getFiles) ▼ getFiles(req, res) │ req.params.id === 'p123' ▼ 查询 SQLite → 返回文件列表 JSON

中间件（Middleware）

中间件是 Express 的核心概念——在路由处理函数之前执行的函数。

类比前端

中间件就像 React 的高阶组件或 Layout 路由——在真正渲染页面之前，先做一些通用处理：

// 前端：Layout 路由（在子路由之前执行）
<Route element={<AuthLayout />}>     ← 检查登录
  <Route path="/dashboard" />          ← 真正的页面
</Route>

// 后端：中间件（在路由之前执行）
app.use(authMiddleware);                ← 检查登录
app.get('/api/dashboard', handler);     ← 真正的处理

中间件的执行顺序

app.use(middlewareA);  // ① 先执行
app.use(middlewareB);  // ② 再执行
app.get('/api/data', handler);  // ③ 最后执行
请求进入 │ ▼ ┌─────────────┐ │ middlewareA │ ← 解析请求体、记录日志 └──────┬──────┘ │ next() ▼ ┌─────────────┐ │ middlewareB │ ← 验证身份、检查权限 └──────┬──────┘ │ next() ▼ ┌─────────────┐ │ handler │ ← 处理业务逻辑，返回响应 └─────────────┘

关键：调用 next()

// 中间件必须调用 next() 才能传递给下一个
function logger(req, res, next) {
  console.log(`${req.method} ${req.path}`);
  next();  // ← 不调用就卡住了！
}

// 不调用 next() 的情况：直接返回响应
function authCheck(req, res, next) {
  if (!req.headers.authorization) {
    return res.status(401).json({ error: '未登录' });  // 直接返回，不调用 next
  }
  next();  // 验证通过，继续
}

Open Design 中的真实路由结构

根据你之前在 apps/daemon/src/routes/ 看到的文件：

server.ts
├── app.get('/api/health')          ← 健康检查（直接定义）
├── app.get('/api/ready')           ← 就绪检查（直接定义）
├── app.get('/api/version')         ← 版本信息（直接定义）

├── app.use('/api/projects', ...)   → routes/project/     ← 项目 CRUD

├── app.use('/api/terminal', ...)   → routes/terminal.ts  ← 终端
